# 2026-10-28：普通生成与长上下文

长上下文读入取得小幅收益，普通生成没有稳定提速。相同权重、输入、输出和容量下，Mia 原生引擎仍快于本版本。本轮没有达到“通用场景超过开源方案”的目标，也没有训练新的基础模型。

## 相同条件的证据

- 所有最终运行使用相同公共计时客户端及 wrapper 哈希。短输入每类 9 次、每次 384 output tokens；8K/32K/128K 冷前缀各 3 次；并发 2/4；另有 128K 后 512-token 输出。
- TP=2、容量 524288、两槽、2048-token chunk、五个 DSpark 草稿。E320 保留视觉塔；A0 两个 Python 对照均关闭视觉塔，与本次原生文本进程一致。原生引擎保留自己的分配器和调度实现。
- E320 最终候选与前、后基线各 58/58 完整响应文本和 token 数相同。A0 的基线、融合版、Mia 三组也是 58/58 相同；A0 回切的 30 个响应均能在候选中逐项匹配。
- 7 个普通/并发提示的分词 token IDs 在 Python 与 Mia 间完全相同；长输入直接使用相同 token IDs，所有请求哈希保留。
- 每次使用独立空 spill 目录，冷前缀 cached=0。这里的“冷”指前缀缓存，不代表操作系统页缓存或 Engram 读缓存全冷。
- 未改变 GPU 功耗或时钟设置，保留 2.5 GiB 主机内存保护。最终测试没有 guard kill；两节点数值遥测和对齐方式在 [资源记录](resource-summary.json)。A0 的余量较小，不能外推到更大的实际输入。
- 保留上游 encoder prefill + 有界 decoder replay；不把这些数据描述为完整精确 decoder prefill。尚未测试 512K 实际输入或 128K 真实代码仓库任务。

## 编程回归

SciCode 固定开发协议：37/50 → 37/50，完整父题 8/15 → 8/15；50 个请求、抽取代码和逐题测试判定均相同。CanItEdit 固定 12 题，两个重复各 7/12 → 7/12；24 个完整文本、代码和判定均相同。失败题保留，不按运行结果重新挑题。

这些结果不等于 Artificial Analysis 官方成绩。冻结协议的 SciCode 参考答案控制此前仅通过 48/50，已知限制仍在第一轮记录中。本轮证明的是限定样本的回归一致性，不宣称所有输入质量无损，更没有证明超过原始模型官方分数。

## 自主实现及未采用路线

新增 GPU 序号 ticket、双段流水线和直接消费接收环的 HC 残差 CUDA 内核。按原 rank 顺序相加、保留 BF16 舍入和 FMA 顺序，减少 gathered 中间张量的读写，注册环约 51 MiB。复用上游 RDMA 注册/代理/完成通知和数值内核；贡献边界见 [设计说明](../../docs/round2-design.md)。

2048 行通信加后处理微基准：3.56 ms → 2.59 ms，约减少 27%；这不是端到端的 27% 提速。双机 eager、CUDA Graph、多形状输出和 100 个载荷变化/错开时序事务通过。尚未对新增 RDMA 路径做实机断链注入。

4090 增量草稿、专家工作列表、持久化队列、fragment 链、控制消息合并和 prompt HC 侧流均有实现与实测。正式候选全部关闭这些路线。远程草稿筛选反而慢约 18–21%；该筛选的重复数、追踪和 GPU 使用不同，不能放进最终公平排名。[负结果和排除项](experiments-and-exclusions.json) 保留具体原因。
